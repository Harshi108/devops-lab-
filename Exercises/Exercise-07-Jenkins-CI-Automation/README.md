\# Exercise 7: Jenkins CI Automation



\## Objective

Understand Continuous Integration (CI) and use Jenkins to automate project validation and testing.



\## Technologies

\- Jenkins

\- Docker

\- Git and GitHub

\- Python

\- Automated testing



\## What is Continuous Integration?

Continuous Integration is the practice of frequently integrating code changes into a shared repository and automatically validating those changes through builds and tests.



\## Benefits

\- Detects errors early.

\- Automates repetitive build and test tasks.

\- Provides feedback about code changes.

\- Improves software quality.



\## Jenkins

Jenkins is an open-source automation server used to build, test, and deploy applications through configurable pipelines.



\## Project Structure

\- `README.md` - Project documentation.

\- `Jenkinsfile` - Defines the CI pipeline.

\- `app.py` - Sample Python application.

\- `test\_app.py` - Automated application tests.



\## Workflow

1\. Store project files in GitHub.

2\. Configure a Jenkins pipeline using the repository.

3\. Check out the source code.

4\. Install dependencies.

5\. Run automated tests.

6\. Review the build result.



\## Jenkins URL

http://localhost:8080



\## Note

Pushing the project files to GitHub does not automatically run Jenkins. Jenkins must be installed and configured separately to execute the pipeline.
